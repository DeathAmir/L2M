FUNCTION CATALOG

Lua functions

Chat messageschat · clientChat · systemChat＋

All three names are aliases of the same function. They add a local message to the Minecraft chat UI; they do not send a server chat packet.

l2m.chat("Hello from Lua!")
l2m.clientChat("Hello again")
l2m.systemChat("Local message")
  • Signature: l2m.chat(message)
  • Argument: string, 1–256 characters; blank messages are rejected.
  • Returns: no useful Lua value (nil).
  • Requires: Minecraft chat UI to be available.
Logginglog＋

Writes a message to the L2M logger with the [Lua] prefix.

l2m.log("Script started")
  • Signature: l2m.log(value)
  • Argument: any Lua value; converted to text.
  • Returns: no Lua value.
HUD drawingdrawText · drawRect · clearDraw＋

Queues simple drawing calls for the client GUI render event. Coordinates are GUI screen coordinates.

l2m.drawText(12, 12, "L2M is active")
l2m.drawText(12, 30, "Custom color", 0xFF50E0D2)
l2m.drawRect(10, 52, 140, 3, 0xFF50E0D2)
l2m.clearDraw()
  • l2m.drawText(x, y, text, color?) — x/y are integers, text is a string (maximum 512 characters), color is an integer and defaults to 0xFFFFFFFF.
  • l2m.drawRect(x, y, width, height, color) — integer coordinates and dimensions; width/height must be 0–4096; color is an integer.
  • l2m.clearDraw() — removes all queued drawing calls.
  • Drawing remains queued until cleared or another script execution clears the bridge.
Generated content definitionsregisterBlock · registerItem＋

These functions save JSON definitions under config/l2m/generated. The current implementation loads definitions during mod initialization, before registry freeze. Restart Minecraft after creating or changing a definition.

l2m.registerBlock("ruby_ore", {
  displayName = "Ruby Ore",
  hardness = 3.0,
  requiresTool = true
})

l2m.registerItem("ruby", {
  displayName = "Ruby",
  stackSize = 16
})

l2m.registerBlock(id, properties)

  • id: lowercase letters, numbers and underscores; 1–48 characters.
  • displayName: optional string stored in the definition (default is the id).
  • hardness: optional number (default 1.5).
  • requiresTool: optional boolean (default false).

l2m.registerItem(id, properties)

  • id: same ID rules as blocks.
  • displayName: optional string stored in the definition (default is the id).
  • stackSize: optional integer (default 64, accepted range 1–99).

Both functions return true after writing the definition. The current registration code creates basic blocks and items; custom models, textures, recipes and runtime registry changes are not provided by these methods.

IN-GAME INTERFACE

Client commands

/l2m run <file>Run a standalone script＋

Executes config/l2m/scripts/<file>.lua. Use the filename without the extension.

/l2m run hello
/l2m package run <package> <script>Run a script from an installed package＋

Executes config/l2m/packages/<package>/scripts/<script>.lua.

/l2m packagesList package directories＋

Lists directory names found in config/l2m/packages.

PACKAGE FORMAT

Auto-run packages

When the player joins a world, L2M scans package folders for a package.json. A valid entrypoint is executed automatically.

config/
└── l2m/
    └── packages/
        └── my_package/
            ├── package.json
            └── scripts/
                └── main.lua
{
  "id": "my_package",
  "entrypoint": "scripts/main.lua"
}

The manifest ID must match the package folder. The entrypoint must be a relative Lua path inside that package folder.

IMPORTANT

Experimental client API

L2M currently runs scripts locally using LuaJ 3.0.1 and a Lua 5.1-compatible environment. The implementation loads LuaJ standard globals; scripts should be treated as trusted code. Timer/event APIs, server-side execution, and live registry edits are not part of the current public API.
