LUA REFERENCE

Lua API

Functions you can call from an L2M script. Each entry shows the arguments, what it does in-game, and a small example.

i
Where these functions work

Scripts run on the Minecraft client. Chat and drawing are client-side. Content definitions are saved to disk and loaded when Minecraft starts.

Chat messages

Use l2m.chat to print a line in your own Minecraft chat. It adds the [L2M] prefix. It does not send anything to a multiplayer server, so other players will not see the message.

l2m.chat(message)Client

l2m.clientChat(message) and l2m.systemChat(message) are aliases. They do exactly the same thing.

main.lua
l2m.chat("Hello, Minecraft!")

local playerName = "Steve"
l2m.clientChat("Welcome, " .. playerName)
ArgumentTypeDetails
messagestringText to display. Empty messages and messages longer than 256 characters are rejected.

Returns: nothing (nil). If the chat UI is unavailable or the text is invalid, the script raises a Lua error.

Writing to the log

l2m.log writes a line to the Minecraft log. Use it while testing a script or checking the value of a variable. The line is marked with [Lua].

l2m.log(value)Client
main.lua
local coins = 125
l2m.log("Script loaded")
l2m.log("Coins: " .. tostring(coins))
ArgumentTypeDetails
valueanyAny Lua value. L2M converts it to text before writing it to the log.

Returns: nil.

Drawing text on the HUD

l2m.drawText draws text over the game interface. The position is measured in GUI pixels, starting at the top-left corner of the screen. The text is drawn again on each HUD frame until you clear it or run another script.

l2m.drawText(x, y, text, color)Client
main.lua
l2m.drawText(12, 12, "L2M is running")

-- ARGB color: opaque turquoise
l2m.drawText(12, 32, "Custom HUD", 0xFF50E0D2)
ArgumentTypeDetails
xintegerHorizontal position in GUI pixels.
yintegerVertical position in GUI pixels.
textstringText to draw. Maximum length: 512 characters.
colorinteger, optionalARGB color. Defaults to 0xFFFFFFFF (opaque white).

Returns: nil. Coordinates and color are read as Lua integers.

Drawing rectangles

l2m.drawRect draws a filled rectangle on the HUD. It is useful for simple backgrounds, separators and bars. The color uses the same ARGB format as drawText.

l2m.drawRect(x, y, width, height, color)Client
main.lua
-- A small turquoise status bar
l2m.drawRect(10, 52, 140, 4, 0xFF50E0D2)

-- A dark panel behind some text
l2m.drawRect(8, 8, 180, 42, 0xCC101820)
l2m.drawText(16, 16, "Player status")
ArgumentTypeDetails
x, yintegerTop-left position in GUI pixels.
widthintegerRectangle width, from 0 to 4096.
heightintegerRectangle height, from 0 to 4096.
colorintegerARGB color value.

Returns: nil. Negative dimensions and dimensions above 4096 cause an error.

Clearing HUD drawings

l2m.clearDraw removes every text and rectangle added by the current script. Call it before drawing a new screen or when you no longer need the HUD elements.

l2m.clearDraw()Client
main.lua
l2m.clearDraw()
l2m.drawText(12, 12, "Fresh HUD")

Arguments: none. Returns: nil.

Registering a block

l2m.registerBlock writes a block definition to config/l2m/generated/blocks/. It does not add a block to the running game immediately. Restart Minecraft after the definition has been written; L2M reads generated definitions during startup.

l2m.registerBlock(id, properties)Startup
main.lua
local ok = l2m.registerBlock("ruby_ore", {
    displayName = "Ruby Ore",
    hardness = 3.0,
    requiresTool = true
})

l2m.log("Block definition saved: " .. tostring(ok))
Argument / propertyTypeDetails
idstring1–48 characters. Use lowercase letters, numbers and underscores only.
properties.displayNamestringSaved as metadata. The current loader does not yet apply it as the in-game display name.
properties.hardnessnumberBlock hardness. Defaults to 1.5; negative values are clamped to zero by the loader.
properties.requiresToolbooleanWhether the block requires the correct tool to drop items. Defaults to false.

Returns: true after the JSON definition is saved. A failure raises a Lua error.

Registering an item

l2m.registerItem saves an item definition in config/l2m/generated/items/. Restart Minecraft to load it into the item registry.

l2m.registerItem(id, properties)Startup
main.lua
l2m.registerItem("ruby", {
    displayName = "Ruby",
    stackSize = 16
})
Argument / propertyTypeDetails
idstring1–48 characters. Lowercase letters, numbers and underscores.
properties.displayNamestringSaved in the JSON file, but not yet used for the item's visible name.
properties.stackSizeintegerStack limit from 1 to 99. Defaults to 64.

Returns: true when the definition is saved. The current manual-script writer saves the supplied stack size without checking its range. The registry loader accepts 1–99; an invalid value is reported in the Minecraft log during startup. Package preload checks this range before saving.

Commands

Enter these commands in Minecraft's chat. They run scripts on your client.

/l2m run <file>

Runs config/l2m/scripts/<file>.lua. Enter the filename without .lua.

/l2m package run <package> <script>

Runs a Lua file from that package's scripts folder. Enter the script name without the extension.

/l2m packages

Lists the package folders found in config/l2m/packages.

Packages

A package lives in config/l2m/packages/<package-id>/. It needs a package.json file and a Lua entrypoint. The package ID must match its folder name.

package.json
{
  "id": "my_package",
  "entrypoint": "scripts/main.lua"
}

At startup, L2M runs the entrypoint once in a registration pass. In that pass, only registerBlock and registerItem do anything; chat, log and drawing calls are ignored. Later, when you join a world, L2M runs the entrypoint again as a normal client script.

Keep registration calls at the top level of the entrypoint. The package entrypoint must be a valid .lua file inside its package folder.

Categories, item definitions and inventory

L2M packages can define categories and catalog entries. Item definitions map to an existing Minecraft item so the Give and Equip actions use real Minecraft inventory stacks, shield behavior and armor slots. These definitions do not register brand-new Minecraft item IDs or change vanilla combat attributes yet.

l2m.defineCategory(id, properties)Content definition

Creates a category with displayName, icon (a registered Minecraft item ID), optional description and sortOrder.

l2m.registerItem(id, properties)Content definition

Defines a catalog item with displayName, description, category, minecraftItem, icon, optional texture, slot, stackSize, armor and toughness. minecraftItem must be a registered item ID. Valid slots are mainhand, offhand, shield, head, chest, legs and feet. Armor/toughness are metadata only; the mapped Minecraft item supplies actual stats.

l2m.openInventory(category?)Client UI

Opens the L2M categorized item catalog. Omit the category to show all entries, or pass a category ID to start filtered. The /l2m inventory client command opens the same screen.

l2m.giveCustomItem(id, count?)Server command

Requests the mapped Minecraft item through /give @s. Count defaults to one. Requires server permission.

l2m.equipItem(id)Server command

Requests the mapped Minecraft item in the configured equipment slot using /item replace. Requires server permission.

l2m.listCategories()Lua table

Returns an array-like Lua table of registered category IDs.

equipment.lua
l2m.defineCategory("shields", {
    displayName = "Shields",
    icon = "minecraft:shield",
    description = "Defensive equipment"
})

l2m.registerItem("iron_guard", {
    displayName = "Iron Guard Shield",
    description = "A shield equipped in the offhand",
    category = "shields",
    minecraftItem = "minecraft:shield",
    icon = "minecraft:shield",
    slot = "offhand",
    stackSize = 1
})

l2m.giveCustomItem("iron_guard", 1)
l2m.equipItem("iron_guard")
l2m.openInventory("shields")

For custom catalog art, place a 16×16 PNG in the mod resources, for example assets/l2m/textures/items/iron_guard.png, and set texture = "l2m:textures/items/iron_guard.png". The inventory screen displays that texture instead of the mapped item's icon.

World interaction and effects

These functions let Lua scripts request TNT, place blocks, create client-side particles and manipulate entities currently loaded on your client. Server-authoritative commands require permission on the current world/server. Client-side entity transforms are visual/local and may be corrected by the server in multiplayer.

l2m.explodeTnt(x, y, z, fuseTicks)Server command

Requests a vanilla primed TNT entity at the given coordinates. The fuse defaults to 40 ticks and must be between 1 and 32767. Requires permission to use /summon.

tnt.lua
l2m.explodeTnt(120, 65, -40, 60)
l2m.setBlock(x, y, z, blockId)Server command

Requests the vanilla /setblock command with the replace mode. The block ID must exist in the Minecraft block registry. Requires command permission.

blocks.lua
l2m.setBlock(0, 64, 0, "minecraft:gold_block")
l2m.spawnParticle(particleId, x, y, z, vx, vy, vz)Client visual

Spawns one particle on the local client. Velocity components are optional and default to zero. This currently supports registered simple particle types, such as minecraft:flame, minecraft:smoke, minecraft:happy_villager and minecraft:cloud.

particles.lua
l2m.spawnParticle("minecraft:flame", 0.5, 65, 0.5, 0, 0.08, 0)
l2m.spawnParticle("minecraft:smoke", 0.5, 65, 0.5, 0, 0.04, 0)
l2m.moveEntity(uuid, x, y, z, vx, vy, vz)Client transform

Moves a currently loaded entity identified by UUID and optionally sets its velocity. The optional velocity must be supplied as all three components. This modifies the client-side entity instance; authoritative server movement can overwrite it.

l2m.setEntityVelocity(uuid, vx, vy, vz)Client transform

Sets velocity on a loaded client entity. This is useful for local visual experiments and client-side entities. It does not grant control over remote server entities.

l2m.launchRocket(speed)Server command

Launches a vanilla fireball from the player's eye position in the direction they are looking. Speed defaults to 1.8 and is limited to 0.1–8.0. Requires permission to use /summon.

rocket.lua
l2m.launchRocket(2.4)

These APIs return true when the local operation or command submission succeeds. A successful command submission does not guarantee the server accepts the command.

Client event subscriptions

l2m.on(eventName, callback) subscribes the current Lua runtime to one of the events listed below. Events are delivered to the client Lua runtime. Callback errors are logged and do not stop other listeners.

l2m.on(eventName, callback)Client
events.lua
l2m.on("player_hurt", function(amount, damageType, health)
    l2m.log("Damage: " .. tostring(amount) .. " from " .. damageType)
end)

l2m.on("player_death", function(damageType)
    l2m.log("Died from " .. damageType)
end)

l2m.on("block_break", function(blockId, x, y, z)
    l2m.log("Broke " .. blockId .. " at " .. x .. ", " .. y .. ", " .. z)
end)

l2m.on("entity_spawn", function(entityType, uuid, x, y, z)
    l2m.log(entityType .. " spawned")
end)
EventArgumentsWhen it fires
client_ticknoneOnce per client tick while in a world. Keep handlers lightweight.
player_joinplayerName: stringWhen the local client joins a world.
player_leaveplayerName: stringWhen the local client leaves a world.
player_hurtamount: number, damageType: string, health: numberAfter the local player takes damage.
player_deathdamageType: stringWhen the local player dies.
player_respawnhealth: numberWhen the local player respawns.
player_attacktargetType: string, targetUuid: stringWhen the local player attacks an entity.
player_eatitemId: string, count: numberWhen the local player finishes consuming a food item.
item_use_startitemId: string, count: numberWhen the local player starts using an item.
block_breakblockId: string, x: number, y: number, z: numberWhen the local player breaks a block.
block_placeblockId: string, x: number, y: number, z: numberWhen the local player places a block.
entity_spawnentityType: string, uuid: string, x: number, y: number, z: numberWhen a non-player entity joins a loaded level.

Event callbacks currently receive primitive Lua values, not a mutable event object. These notifications are observational; the current API does not expose event cancellation. Events that originate on the logical server are supported in singleplayer/integrated worlds. Receiving server-originated events on a remote multiplayer server requires a server-side L2M bridge.

Giving an item

l2m.giveItem(itemId, count) requests the vanilla /give @s command through the active connection. It requires permission to use /give on the current world or server.

l2m.giveItem(itemId, count)Client command
main.lua
l2m.giveItem("minecraft:totem_of_undying", 1)

itemId must be a registered Minecraft item ID and count must be between 1 and 64. The function returns true when the command is sent; the server may reject it if you lack permission.

Listeners are cleared when leaving the world. Package entrypoints register their listeners during normal client execution after joining a world.
