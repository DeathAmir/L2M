Script packages

A package groups Lua scripts and a manifest so they can be discovered and launched through L2M.

Directory layout

config/l2m/packages/my_package/
my_package/
├── package.json
└── scripts/
    └── main.lua

The package ID must match its directory name. The manifest must be named package.json, and its entrypoint must point to a Lua file inside the package directory.

Manifest format

package.json
{
  "id": "my_package",
  "entrypoint": "scripts/main.lua"
}

Package loading

At startup, L2M runs the entrypoint once in a registration pass. During that pass, only l2m.registerBlock and l2m.registerItem perform registration work; chat, logging and drawing calls are ignored. When you later join a world, L2M runs the entrypoint again as a normal client script.

Package management

Use the built-in package commands to inspect and maintain installed packages. A disabled package remains on disk but is skipped by automatic world-join execution and startup registration preload.

Minecraft chat
/l2m package validate hello-world
/l2m package info hello-world
/l2m package disable hello-world
/l2m package enable hello-world
/l2m package remove hello-world

Validation checks the package folder ID, JSON manifest, Lua entrypoint and dependencies. Dependencies are declared as package IDs in the dependencies array and must already be installed. Removing a package deletes its entire directory, including assets and scripts.

Run a package script

Minecraft chat
/l2m package run my_package main
/l2m packages
Registration timing

Generated block and item definitions are read during Minecraft startup. Restart the game after changing those definitions.
